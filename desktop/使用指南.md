# PDFMathTranslate 项目分析与 Windows 使用指南

核对日期：2026-10-13。来源：https://github.com/Lei-Ao/PDFMathTranslate

已克隆到 `F:\AiProject\PDFTranslation\PDFMathTranslate`，分支 `main`，提交 `6911a903`（2026-10-12），包版本 `1.9.12`。当前电脑 Python 为 3.12.1，满足 `>=3.11,<3.13`。本次完成源码拉取和静态分析，尚未安装依赖或进行实际 PDF 翻译。

## 项目做什么

这是面向科学论文的 PDF 翻译工具，重点是保留页面布局、公式和图形。支持 CLI、Gradio 网页界面、Docker、Python 调用及可选 HTTP/MCP 接口。翻译服务可以选择 Google、Bing、DeepL、OpenAI 兼容服务、DeepSeek、Ollama 等。

普通模式处理流程：读取 PDF → DocLayout-YOLO/ONNX 识别布局 → PDFMiner 提取字符并重组段落、保护公式 → 多线程调用翻译服务 → 将译文重新排版写入 PDF → 输出译文和双语文件。PyMuPDF 负责 PDF 操作，SQLite 缓存减少重复翻译。

| 文件 | 作用 |
|---|---|
| `pdf2zh/pdf2zh.py` | 命令行入口、参数、界面及内核路由 |
| `pdf2zh/high_level.py` | 文件/字节流翻译、OCR、PDF 输出 |
| `pdf2zh/converter.py` | 段落分析、公式保护、翻译和排版 |
| `pdf2zh/doclayout.py` | ONNX 布局模型及 CPU/CUDA/DirectML 选择 |
| `pdf2zh/translator.py` | 各翻译服务的适配器 |
| `pdf2zh/gui.py` | Gradio 网页界面 |
| `pdf2zh/cache.py`、`config.py` | 翻译缓存及配置 |
| `pdf2zh/kernel/` | 默认 fast 内核及隔离运行的 precise 内核 |

CPU 可以运行，不要求 GPU。公式保护依赖布局、字体和字符规则，复杂表格、特殊字体和扫描件仍应检查输出。它不会训练翻译模型，翻译质量和耗时取决于选择的服务、网络及 PDF 本身。

## 安装已拉取的源码

以下命令在 PowerShell 中执行。直接调用虚拟环境程序，无需激活环境或修改执行策略。

```powershell
cd F:\AiProject\PDFTranslation\PDFMathTranslate
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\pdf2zh.exe --version
```

`pip install -e .` 安装这个已克隆的仓库；`pip install pdf2zh` 安装的是 PyPI 发布包，代码可能与此仓库不同。

## 桌面版：双击即用的窗口应用

2026-10-14 新增。桌面版把网页界面包进一个独立窗口（用 Windows 自带的 WebView2 内核），
不用开浏览器、不用手动启动服务，关掉窗口程序就退出；翻译功能和网页版完全一致。

| 文件 | 作用 |
|---|---|
| 桌面快捷方式「PDF 翻译工具」 | 双击启动（平时用这个） |
| `启动桌面版.vbs` | 同上；在项目文件夹里直接双击也可以 |
| `desktop_app.py` | 启动器本体（启动界面服务、开窗、关窗退出） |
| `desktop.ico` | 窗口和快捷方式图标 |
| `desktop.log` | 运行日志，出问题先看这里 |

> 系统缺少 WebView2 运行时时程序会**自动**改用 Edge/Chrome 应用窗口，不需要额外入口。
> 需要手动强制这一模式时，可运行 `PDF翻译工具.exe --app-window`。

使用要点：

- 启动后先显示几秒启动画面（首次加载模型稍慢），随后进入上传页面。
- 结果文件按任务保存在 `data/translations/<任务ID>/`（源码桌面版默认位于 `F:\AiProject\PDFTranslation\data\translations\<任务ID>\`）；同名文档每次翻译都有独立目录。
- “最近译文”显示多条历史，点击条目可继续阅读；窄屏时在页面内展开或折叠列表。旧结果仍可发现，兼容目录见下文“历史列表与翻译数据目录”。
- 点"下载译文 PDF / 双语 PDF"会弹出 Windows 标准的"另存为"对话框。
- 关窗即退出程序；翻译过程中关窗会中止本次翻译。
- 重复双击只会提示"已经在运行"，不会开第二个实例。
- 桌面版依赖装进 venv 的 `pywebview` 包；以后若重建虚拟环境，需要补装：
  `PDFMathTranslate\.venv\Scripts\python.exe -m pip install pywebview`
- 排查问题看 `desktop.log`；需要开发者工具时先设置环境变量 `PDF2ZH_DESKTOP_DEBUG=1` 再启动。

网页版仍然可用（见上一节），两种方式启动的是同一套界面和功能。

## 历史列表与翻译数据目录

2026-10-17 更新。“最近译文”按条目展示历史，长文件名可通过元信息的完整名提示查看，点击条目继续阅读。桌面侧栏内的列表独立纵向滚动；1050px 以下侧栏收窄，760px 以下隐藏原侧栏，历史列表转为页面内可折叠区域，仍可访问。桌面端“新建窗口”位于侧栏底部、工作空间说明上方。

新任务的原文与翻译产物统一放在 `data/translations/<任务ID>/`，每次任务使用独立目录，同名文件不会覆盖已有任务。默认位置由启动入口决定：

| 启动方式 | 默认翻译数据根目录 |
|---|---|
| 源码桌面版 `desktop_app.py` | 脚本所在项目目录的 `data/` |
| 网页启动器 `start_webui.py` | 脚本所在项目目录的 `data/`，与启动时的工作目录无关 |
| 免安装桌面版 | exe 所在目录的 `data/` |
| 安装版或 exe 目录不可写 | `%LOCALAPPDATA%\PDFMathTranslate\data\` |

两个启动器在导入界面前用 `setdefault` 设置 `PDF2ZH_DATA_DIR`。可预先将该环境变量设为自定义的绝对路径；已有设置不会被启动器覆盖，任务保存到该根目录下的 `translations/<任务ID>/`。直接运行 `pdf2zh -i` 不经过这两个启动器，明确指定目录时可先设置同一环境变量。

历史列表继续发现以下三个已知旧目录中的文件组：

- 项目根目录 `F:\AiProject\PDFTranslation\pdf2zh_files\`
- 内层源码目录 `F:\AiProject\PDFTranslation\PDFMathTranslate\pdf2zh_files\`
- 用户目录 `%LOCALAPPDATA%\PDFMathTranslate\pdf2zh_files\`

旧 PDF 留在原位，不自动搬移、删除或覆盖；不同目录中的同名记录分别保留并标注来源，只去掉相同实际路径的重复记录。本次只整理翻译运行数据，`desktop.log`、接口配置、浏览器缓存、模型/字体缓存和翻译缓存均继续使用原位置。

## 免安装 exe 版

2026-10-14 新增。把桌面版打包成不依赖 Python 的独立程序：整个文件夹拷到别的
Windows 电脑上双击即可使用（目标电脑不需要装 Python，也不需要本项目源码）。

构建命令（在打包机上执行一次即可）：

```powershell
cd F:\AiProject\PDFTranslation
.\PDFMathTranslate\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean --distpath dist --workpath build desktop_build.spec
```

产物：`dist\PDF翻译工具\`（约 470 MB，onedir 形式）

| 内容 | 说明 |
|---|---|
| `PDF翻译工具.exe` | 双击启动；必须连同 `_internal\` 一起拷贝，不能只拷 exe |
| `_internal\` | 依赖与前端资源 |
| `使用说明.txt` | 构建时自动生成，给最终使用者看 |
| `data/translations/<任务ID>/` | 首次翻译时自动创建，每个任务保存各自的原文与翻译产物 |
| `desktop.log` | 运行日志 |

打包版与源码版的差别：

- 应用工作目录在 exe 旁边；若 exe 放在不可写的位置（如 Program Files），或目录里有
  `installed.marker`（安装包会放），自动改用 `%LOCALAPPDATA%\PDFMathTranslate`；
  新翻译任务位于该工作目录下的 `data/translations/<任务ID>/`，日志和浏览器缓存仍在原位置。
- 模型与字体仍下载到 `%USERPROFILE%\.cache\babeldoc`，与源码版共用；换电脑后
  首次翻译需要联网下载约 160 MB。
- 已强制客户端渲染（不含 SSR 的 node 运行时）；precise 内核依赖独立虚拟环境，
  打包版不可用，fast 模式的常规翻译不受影响。
- 系统缺少 WebView2 运行时时自动改用 Edge 窗口打开，不会启动失败。
- 重复双击会把已打开窗口带到前台（最小化会自动还原），不再只是弹提示。想在同一个程序里
  同时干两件事（比如一边读一边翻），用界面里的"⧉ 新建窗口"，见下文"本地改动三"。
- exe 带版本信息（属性面板可见），发行版本号、发布者、源码链接统一在
  `desktop_version.py` 里维护，改一处即可，重打时自动生效。

## 翻译进度浮层（本地改动二）

2026-10-15 新增。原先点"开始翻译"后界面只有一条很细、不带文字的进度条（Gradio 的
`gr.Progress()` 只在传入"第几/共几"这种整数对时才显示文字，上游传的是小数比例，
所以界面看起来毫无反应），翻译一篇 20 页论文要等约 4 分钟，很容易被误认为"没有在翻译"，
甚至中途关窗导致前功尽弃。现在翻译时会在上传区上盖一块浮层：

- 位置：**直接覆盖在「上传文档」拖放区上**（半透明浮层，带虚线边框，尺寸与上传区一致）；
  空闲时完全不显示，不影响正常上传
- 内容：大号百分比、当前阶段、第 N / M 页、已用时间、预计剩余时间
- 阶段：正在准备翻译 → 正在翻译文档 → 正在生成 PDF → 翻译完成
- 进度条带流动动画，即使百分比暂时不动也能看出程序在跑
- 浮层显示期间会挡住上传区（翻译中不该再换文件）；失败 / 取消的浮层可穿透点击，
  重新选择文件时自动清空；翻译完成后浮层自动收起

实现方式（改动文件：`pdf2zh/gui.py`、`pdf2zh/upload.css`）：

| 位置 | 改动 |
|---|---|
| `translate_file` | 由普通函数改为**生成器**：翻译放进后台线程，主线程每 0.4 秒 yield 一次进度 |
| 每个会话的 `state["progress"]` | 后台线程写入、界面读取的进度格（`new_progress()` 建、带锁）；多窗口时各看各的 |
| `progress_html()` | 把快照渲染成浮层 HTML（`done` / `idle` 返回空串即收起） |
| `_stream_outputs()` | 中间帧只更新浮层，其余输出用 `gr.skip()` 保持不变 |
| 上传表单布局 | `file_input` 与进度组件一起放进 `gr.Column(elem_id="upload-dropzone")`，浮层据此定位 |
| `translate_btn.click` | 加 `show_progress="hidden"`，并去掉 `progress=gr.Progress()` 形参与所有 `progress()` 调用 |
| `upload.css` | `#upload-dropzone` 设为定位容器，`.tr-progress` 系列为浮层样式 |

> 为什么要去掉 `gr.Progress()`：浮层已经覆盖上传区，Gradio 自带的进度条会同时渲染出来
> （带"正在翻译文档… - 65.0%"、`N/M steps` 和关闭按钮），两条进度叠在一起很乱。
> 关掉后由浮层单独显示。注意 `progress` 形参原本参与参数位置对齐，删掉后
> `*envs` 直接跟在 `state` 后面，拼接顺序不变（勿在 `state` 与 `*envs` 之间再插参数）。

> 这是第二处本地改动。同步上游时除发行信息行外，这段也要重新应用
> （`gui.py` 与 `upload.css` 两个文件）。打包/安装流程不变。
> 回归检查：`PDFMathTranslate\.venv\Scripts\python.exe .gui-test\check_progress_plumbing.py`
> （用假内核跑一遍 translate_file，不联网）。

## 多窗口：一边读，一边翻（本地改动三）

2026-10-16 新增。在对照阅读页看一篇文献时想翻译另一篇，以前只能先退回上传页再上传新文件；
而翻译完成后整个窗口会被新译文"抢"走（界面自动跳到新译文的阅读页），手上这篇的阅读位置就没了。
现在可以再开一个窗口：

- 入口一：工作台左侧栏"最近译文"下方的 **⧉ 新建窗口**
- 入口二：对照阅读页右上角 **•••** 菜单里的 **在新窗口开始新的翻译**（阅读时不用离开当前页）
- 新窗口连的是同一个本地服务（同一份翻译结果目录、同一份模型设置），但是**独立会话**：
  各自上传、各自翻译、各自显示进度
- 于是常见用法变成：窗口 A 停在某篇文献的对照阅读页，窗口 B 里上传并翻译另一篇；
  B 完成后自动跳到 B 的阅读页，A 原样不动
- 关掉其中一个窗口不影响另一个，最后一个窗口关闭时程序才退出
- 翻译仍然一次只跑一篇（Gradio 队列默认并发 1）：第二个窗口点"开始翻译"会排队等前一篇结束，
  不会两个翻译同时抢模型和接口

实现方式（改动文件：`desktop_app.py`、`pdf2zh/gui.py`、`pdf2zh/reader/index.html`、
`pdf2zh/reader/reader.js`、`pdf2zh/upload.css`）：

| 位置 | 改动 |
|---|---|
| `desktop_app.WindowBridge` | 用 pywebview 的 `js_api` 暴露 `open_window(path)`，从非主线程再开一个原生窗口（同一服务、同一 WebView2 配置目录）；只接受本站路径 |
| `run_native_window` | 首个窗口也带 `js_api=WindowBridge(port)`，新窗口自动拿到同样的桥 |
| `open_new_window_js`（`gui.py`） | 页面通用脚本：有 `window.pywebview.api` 就走桥，没有则退回 `window.open` |
| `new_window_btn` | 侧栏"⧉ 新建窗口"，`fn=None` 的纯 JS 事件，不占用服务端请求 |
| 阅读页菜单 | 新增"在新窗口开始新的翻译"，同一段逻辑写在 `reader.js` |
| 进度状态 | 由模块级全局改成每会话的 `state["progress"]`，浮层初值给空串，新窗口不会再顶着别的窗口的进度条 |

> 为什么用 pywebview 的 js_api 而不是 `window.open`：桌面版的窗口是 WebView2，不是浏览器，
> `window.open` 打不开新窗口。有桥时走桥，没桥时（网页版、Edge 应用窗口模式、打包版缺
> WebView2 运行时的兜底方式）才退回 `window.open`。

> 这是第三处本地改动。同步上游时除前两处外，这段也要重新应用（`desktop_app.py` 是本项目
> 自己的文件，一般不会被覆盖）。回归检查：
> `PDFMathTranslate\.venv\Scripts\python.exe .gui-test\check_multi_window.py`
> （会临时开两个原生窗口，验证完自动关掉）。

安装包行为：

- 默认装到 `%LOCALAPPDATA%\Programs\PDF 翻译工具`，**不需要管理员权限**（PrivilegesRequired=lowest）
- 创建开始菜单项（程序、使用说明、卸载）与桌面快捷方式（安装时可勾选）

## 发布新版本到 GitHub Releases

源码仓库：https://github.com/Lei-Ao/PDFMathTranslate （fork 自 Byaidu/PDFMathTranslate）。
安装包**不进代码仓库**（GitHub 仓库单文件上限 100 MB），而是作为 Release 附件发布。

发一次新版（2026-10-15 发布 v1.0.0、2026-10-16 发布 v1.0.1，用的都是这套流程）：

1. 改版本号：编辑 `desktop_version.py` 里的 `VERSION`
2. 重打两样（各 1–2 分钟）：

```powershell
cd F:\AiProject\PDFTranslation
.\PDFMathTranslate\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean --distpath dist --workpath build desktop_build.spec
& "$env:LOCALAPPDATA\Programs\Inno Setup 6\ISCC.exe" "installer\PDF翻译工具.iss"
```

3. 提交源码并推送：

```powershell
cd PDFMathTranslate
git add -A
git -c user.name="Lei-Ao" -c user.email="323227518+Lei-Ao@users.noreply.github.com" commit -m "release: v1.0.1"
git -c "http.https://github.com.proxy=" push origin main
```

4. 发布附件（自动建 Release、上传附件、打印上传进度）：

```powershell
.\PDFMathTranslate\.venv\Scripts\python.exe publish_release.py
```

三个必须记住的坑（都是首次发布时踩到的）：

- **GitHub 不接受非 ASCII 附件名**：中文名会被替换成"."（`PDF翻译工具安装包-1.0.0.exe`
  变成了 `PDF.-1.0.0.exe`），所以 `publish_release.py` 上传时统一用
  `PDFTranslate-Setup-<版本>.exe`。
- **提交邮箱会公开**：本机 git 全局邮箱是 `lisupoue@gmail.com`，直接用 `git commit`
  会把它写进公开历史。上面命令用 `-c` 临时指定 GitHub 匿名邮箱；建议把全局配置也改掉
  （`git config --global user.email "323227518+Lei-Ao@users.noreply.github.com"`）。
- **代理**：`~/.gitconfig` 里有 `http.https://github.com.proxy = http://127.0.0.1:7897`，
  代理没启动时 git 推送会直接失败（命令里用 `-c` 临时清掉）。本机直连 github.com
  时快时慢，下载/上传卡住时先启动代理再试。

## 命令行翻译

把 `document.pdf` 放入项目目录，或者改成实际 PDF 的绝对路径。建议首次只翻译前两页。

```powershell
# Google 无需 API Key，但需要能够访问服务
.\.venv\Scripts\pdf2zh.exe ".\document.pdf" -li en -lo zh -s google -p 1-2 -o ".\output"

# 全文翻译
.\.venv\Scripts\pdf2zh.exe ".\document.pdf" -li en -lo zh -s google -o ".\output"
```

普通模式输出 `output\document-mono.pdf`（译文版）和 `output\document-dual.pdf`（原文与译文交替分页）。指定页码只翻译选定页，其余页面保留，不是裁剪 PDF。

常用参数：`-li` 源语言、`-lo` 目标语言、`-s` 服务、`-o` 输出目录、`-p 1-3,5` 选择页码、`-t 4` 翻译并发数、`--ignore-cache` 强制重新翻译。普通模式默认 4 个翻译线程；服务限流时可降为 `-t 1`。

## 使用其他翻译服务

DeepSeek（填写自己的 Key）：

```powershell
$env:DEEPSEEK_API_KEY = "你的 API Key"
$env:DEEPSEEK_MODEL = "deepseek-chat"
.\.venv\Scripts\pdf2zh.exe ".\document.pdf" -s deepseek -li en -lo zh -p 1-2 -o ".\output"
```

OpenAI 兼容接口（地址和模型名以服务商提供的值为准）：

```powershell
$env:OPENAI_BASE_URL = "https://你的服务地址/v1"
$env:OPENAI_API_KEY = "你的 API Key"
$env:OPENAI_MODEL = "你的模型名称"
.\.venv\Scripts\pdf2zh.exe ".\document.pdf" -s openai -li en -lo zh -o ".\output"
```

已有运行中的 Ollama 且已下载模型时：

```powershell
$env:OLLAMA_HOST = "http://127.0.0.1:11434"
$env:OLLAMA_MODEL = "你已下载的模型名称"
.\.venv\Scripts\pdf2zh.exe ".\document.pdf" -s ollama -li en -lo zh -o ".\output"
```

调用在线服务会发送待翻译文本，并可能产生服务商费用。代码会将部分服务配置（包括 Key）保存到用户目录 `.config\PDFMathTranslate\config.json`，因此环境变量并不意味着 Key 只存在于当前终端。

## 可选模式

有可提取文字、布局简单的 PDF，可以试用 ultrafast：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[ultrafast]"
.\.venv\Scripts\pdf2zh.exe ".\document.pdf" --ultrafast -s google -t 4 -o ".\output"
```

该模式跳过 ONNX 布局模型和 OCR，默认并发为 16；无原生文字的页面不进行 OCR，跳过字体子集化会增加文件体积。不能与 GUI、precise、服务器模式等组合。公式或表格复杂时先用普通模式。

扫描 PDF 的实验性 OCR：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[ocr]"
.\.venv\Scripts\pdf2zh.exe ".\scan.pdf" -li en -lo zh -s google -o ".\output"
```

普通模式会自动检测无文本且有图像的页面并尝试 OCR，首次可能下载语言数据。混合文本与扫描区域的页面仍有限制。

实验性 precise 内核使用另一个仓库的代码，并创建隔离环境：

```powershell
git submodule update --init pdf2zh/kernel/PDFMathTranslate-next.git
.\.venv\Scripts\pdf2zh-setup-precise.exe
.\.venv\Scripts\pdf2zh.exe ".\document.pdf" --mode precise -s google -li en -lo zh -o ".\output"
```

此次未初始化这个可选子模块；普通 fast 模式不需要它。
